# FreightHub 网页版 · 稳定性说明（2026-11-02）

## 1. 先说结论：为什么"放一会就授权失效"
截图里所有平台同时报「网络请求失败 / OIS 授权网络请求失败」，**不是授权过期**：
- 欣航是公开网页，根本没有授权，也一起失败；
- 雨桐/环洋/中航的 token 是缓存在数据库里的，过期会自动重新获取；
- 日志里每一次失败都是同一种：**从 Vercel（日本东京机房）连到国内服务器时，TCP 连接发出去没有回应，等到系统超时（约 16 秒）才报错**，而且是 5 个国内站点**同时**失败。

也就是"东京机房 → 国内"这条国际线路偶发性黑洞，持续几分钟后自己恢复；代码里的"授权"字样只是错误信息的包装。我们能做的是：让它失败得快、自动重试、别互相拖累、把原因说清楚；**线路本身我们改不了**（见第 6 节的根治办法）。

## 2. 这次做了什么（都已上线 https://freight.gaosichun.dev）
| 项目 | 做法 |
|---|---|
| 默认对接方式 | 所有平台默认「开放平台API授权」；登录模式只作备用。某平台没填 API 密钥但填了登录账号时，会"暂用登录"，账号页标注「（暂用，未配置开放平台API）」，不会直接报错 |
| 超时 | 连接超时 6 秒（原来要等约 16 秒），读取超时按平台设；单个平台总时限 50 秒（Vercel 函数上限 60 秒），桌面版 240 秒 |
| 重试 | 连接类错误（超时/拒绝）自动换全新连接最多试 3 次（间隔 0.3s、0.8s）；HTTP 429/502/503/504 退避重试 1 次（尊重 Retry-After，最多等 3 秒）；读取超时不重试（避免重复扣时间） |
| token 自动刷新 | OIS（雨桐/环洋/中航API）token 缓存约 3 小时，过期或被拒自动重新 getAuth 再试一次；云途 token 同理，401/403 时强制刷新并换签名写法再试；顺丰同理 |
| 限频/退避 | 429 按 Retry-After 退避；同一平台连续失败进入熔断（见下） |
| 熔断隔离 | 同一服务器实例内某平台连续网络失败 3 次，15 秒内不再请求它，直接提示"暂停 15 秒"，不拖慢其他平台；各平台互不影响（一个失败其它照常返回） |
| 错误分类 | 每个失败都带中文类别：【网络】连不上/超时、【授权】账号密码/密钥/token 被拒、【配置缺失】没填账号或密钥、【平台错误】对方返回异常/不支持该国家 |
| 登录防锁 | 保持"每次最多登录一次，授权失败立即停止，且被锁定的账号不再自动重试"；**网络类失败不会触发锁定** |
| 自愈 | 一次查询里 ≥3 个平台全是【网络】失败时，服务器实例会在处理完后自行退出换新实例，前端提示"检测到网络波动"并最多自动重试 3 次（每次间隔约 3.5 秒）。注意：这只对"实例级"网络故障有效，若是机房出口 IP 被丢包则无效（目前观察到出口 IP 不变） |
| 诊断 | 管理员接口 `GET /api/diag/net`：实例号、出口 IP、对 5 个国内站点做 TCP 探测（一眼看出哪个通哪个不通）；`POST /api/diag/recycle`：手动换实例（有审计记录） |
| 全场最低防呆 | 见第 4 节 |

## 4. 云途为什么登录模式只能在桌面版
云途登录页用的是**阿里云验证码 2.0**（滑块/拼图一类的行为验证码，不是输入字符的图片），要在真实浏览器里拖动、并写入浏览器 Cookie。Vercel 上没有浏览器，也不能"把图片弹给用户输入"。所以网页版云途只能走开放 API（appId/appSecret）；桌面版用本机 Chrome 登录。

## 5. 数据准确性 & 全场最低
- 欣航 vs 官网公开报价页：美国 1kg、新西兰 0.3kg(0932)、德国 2kg 三组，**36/25/41 个渠道逐条核对，价格零差异**。
- 发现并修复的问题：「全场最低」原来是对所有行取最小值，会被以下内容污染：
  1. 雨桐 `HKZ-01中港` ¥1.50（深圳→香港的陆运，不是寄到美国的价格）；
  2. 燕文沙箱的测试价（如 ¥3.2 的 UPS、¥10.9/13/16 的"香港化妆品专线"）；
  3. 币种不是人民币的行（数值小但不可比）。
  现在这些行**仍然显示**，但带「不计入最低」标签（鼠标悬停看原因），不参与全场最低、平台最低价，历史记录的最低价也跳过。规则：备注含"测试环境数据"、渠道名含 中港/港段/境内段/头程/入仓/仓储/HKZ、币种非人民币、重量≥0.2kg 且总价<¥10。
- 其它平台（中航/环洋/雨桐/燕文/云途/顺丰）的官网价格需要登录各自门户才能看，不能自动核对，见回复里的清单。

## 6. 根治办法（如果黑洞仍频繁出现）
1. 在香港/深圳放一台很小的中转服务器（几十元/月），网页版所有对国内平台的请求都经它转发；
2. 或把 Vercel 函数区域换成离国内线路更好的机房（Hobby 套餐只能选 1 个区域）；
3. 或这类查询交给桌面版（国内网络直连）。

## 测试环境 / 正式环境（2026-11-02）

每个开放平台（燕文、云途、顺丰、雨桐、环洋、中航）在「平台账号」里都有「正式环境 / 测试环境」单选，两套凭据和接口地址分开保存，互不覆盖；欣航只有公开报价网页，只显示「正式环境」。

- 存储：正式环境 = 原字段名，测试环境 = `字段名@sandbox`；`env` 记录当前使用的环境。切换环境只改 `env`，另一套原样保留。旧版「单套凭据 + env=沙箱」首次保存时自动迁移为测试环境凭据；顺丰旧的 `sb_xxx` 沙箱字段读取时并入测试环境。
- 共用字段（燕文 cityId、顺丰接口平台 / 产品码 / 寄件邮编、OIS 产品码）不分环境。
- 地址：燕文 正式 https://open.yw56.com.cn/api/order，测试 https://open-fat.yw56.com.cn/api/order（公开测试账号 100000）；云途 正式 / openapi-sbx.yunexpress.cn；顺丰 api-ifsp.sf.global / api-ifsp-sit.sf.global；OIS 没有公开测试域名，测试环境必须自己填「接口域名」，不会回退到正式域名。
- 结果：测试环境返回的行带 env=sandbox + 备注「【测试环境数据，非真实报价】」，界面显示【测试】徽标，标「不计入最低」，不参与全场最低 / 平台最低 / 历史最低价。
- 导入 / 导出账号表的「环境」列沿用 prod / sandbox（也认 正式 / 测试 / 沙箱）。
- 权限：没有「账号管理」权限的角色看不到任何环境的字段值。
